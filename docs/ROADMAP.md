## 下一步（按依赖顺序）

### 1. 感知栈（实机读屏）— 当前瓶颈

没有它，`ato/fidelity` 里那套"用真实对局校验模拟器"的机制拿不到输入，
信任台账就永远停在 `IMITATION`，`allows_training` 永远是 `False`。
这不是一个可以往后放的模块，**它是让其余一切开始产生意义的那一环**。

需要读出的量（都是屏幕上确定性可见的）：DP 计数、生命值、击杀/总数、
干员卡的可用与冷却、已部署单位的位置与朝向、技能就绪光效、暂停/加速状态。

### 2. 模拟器标定（需要 1）

按 `SIM_SPEC` §D 的对拍协议跑：同关卡 + 同队伍 + 同动作脚本，模拟器与实机各一次。
先测 B-1 `move_tiles_per_second`（blast radius 最大），再依次收 B 节其余参数。
**在这一步之前，`ato/train` 的任何东西都不该真的训练。**

### 3. 模仿学习 → 搜索 → RL → 蒸馏

- 模仿：MAA 作业语料（约 40,854 份 / 282,000 条专家动作）做行为克隆的起点。
  注意它的结构性缺陷（RECON §3）——它是"抄作业"的分布，不是"会玩"的分布。
- 搜索即教师（Expert Iteration），Ranked Reward 替代 PvE 里不存在的自我对弈。
- 蒸馏成快策略，满足"跟得上关卡节奏"。

### 4. 自进化循环与门禁

泛化按四切片报告（见过的关 / 没见过的关 / 没见过的干员 / 没见过的练度），
对抗课程走白名单扰动算子 + 可解性过滤。

## 待用户决策（挡不住上面任何一步，但会改变性价比）

见 `docs/RECON.md` §7。三件：

1. **战斗回放日志**——服务端存着每关的精确动作序列与随机种子，是校准的 exact oracle，
   但要非官方 API 客户端，**有账号风险**。
2. **解包 4 个客户端 bundle**（5.2 MB）——拿 2,677 条弹道速度与 922 个技能时序字段，
   公开 JSON 里完全没有。SIM_SPEC E-6 在等这个。
3. **B 站视频预算**——建议 200–400 小时，买的是分布广度而不是标签数量。

---

## 不要走的捷径

- 为了让流程跑通而静默忽略未知机制键。查不到就是 `NoveltyEvent`，strict 下就是抛异常。
- 用 sim-vs-sim 的一致性给关卡晋级信任等级。两次模拟跑得像，跟真实游戏无关。
- 在浮点里累加定时。见 CLAUDE.md §1 与 SIM_SPEC E-1：这类误差不会被标定暴露，只会被它吸收。
