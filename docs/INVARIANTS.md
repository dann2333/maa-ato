# ATO 不变量

这些是**架构级约束**，不是建议。每条都配了执行机制——靠自觉维持的约束等于没有约束。
改动本文件需要明确的理由；违反其中任何一条的代码不应合入。

---

## I-1 纯视觉 + 触控

**约束.** 线上智能体与游戏之间只有两条通道：读屏幕、发触控。禁止内存读写、hook、
注入、封包解析、修改客户端、以及任何从游戏进程内部取状态的手段。

**动机.** 用户明确要求。次生好处是它强制了一个正确的问题定义：能从像素解决的问题，
才是这个游戏真正的问题。任何依赖特权通道的方案都在解一个更容易、但不存在的问题。

**执行.**
- `ato.control.base.DeviceController` 只暴露 `screencap / tap / swipe / long_press`。
  给它加一个"读游戏状态"的能力就是违反本条。
- 离线模拟器属于**训练与规划器件**，由公开静态数据构建；它永远不是运行时的信息通道。
- 见 I-3：策略网络的输入必须逐特征标注可感知性并硬断言。

---

## I-2 适应练度，而非记住干员

**约束.** 策略必须以**属性**为条件，而不是以身份为条件。同一个干员在不同精英化 /
等级 / 专精 / 潜能 / 模组 / 信赖下，对策略而言就是不同的单位。

**动机.** 用户要求："可以适应不同的干员状态，而并非简单的抄作业"。一个把 char_id
查表当主输入的网络，学到的是"这张图该放银灰"，而不是"这个位置需要一个能挡两个、
攻击间隔 1.3 秒、有部署后立即回费的单位"。前者换个账号就废了。

**执行.**
- 干员一律编码为解析后的属性向量：`Stats` 全字段 + 攻击范围格子 + 技能 sp 参数
  (`sp_type/sp_cost/init_sp/duration`) + 天赋 blackboard 数值 + 特性标签。
- 身份嵌入若存在，只能是**可丢弃的辅助输入**：训练时以概率 p≥0.5 置零，
  并在评估中报告"关掉身份嵌入后的性能下降"，该下降必须小于阈值。
- 训练时对练度做域随机化：phase / level / mastery / potential / module / trust 随机采样。
- 评估集必须包含**训练期从未出现的干员**与**未见过的练度组合**，并单独报告其指标。
- 动作头不得是"固定干员槽位"的分类头；用指向当前实际可用卡与可部署格的
  pointer / attention，这样队伍换人不需要改网络。

## I-3 特权只进 critic，不进 policy

**约束.** 模拟器能提供而摄像头不能提供的一切信息（敌人精确血量、未来波次表、
路线全图、技能内部计时器、随机种子），只允许进入
(a) 训练时的 critic / value 网络，(b) 教师策略的监督目标。
**绝不允许**进入学生策略的输入。

**动机.** 用户指出："特权教师应当谨慎处理特权和离线对抗，以免出现不当的过拟合和
hack rewarding"。非对称 actor-critic 与"作弊教师"蒸馏都是有效的方法，但它们的正确
用法是：教师用特权算出**好动作**，学生只从可感知的观测学会**复现这个动作**。一旦特权
泄漏进策略输入，线上必然崩溃，而离线指标完全看不出来。

**执行.**
- `ObservationSpec` 为每个特征标注 `realizable_from_pixels: bool`，并记录"由哪个感知
  组件产出"。策略网络构造时对其输入规格做硬断言，含不可感知特征直接抛异常。
- 教师与学生共享同一份特征命名空间，差别只在于 mask，杜绝两套代码悄悄发散。
- 每次蒸馏后跑一次**特权消融**：把特权特征替换为感知估计值（含其真实误差分布），
  性能下降超过阈值即判定为泄漏。

## I-4 奖励不可被刷

**约束.** 主奖励只用游戏自身的成败判据：是否通关、三星条件、漏怪数、剩余生命。
任何 shaping 都必须是 **potential-based shaping**（Ng, Harada & Russell, 1999），
形如 `F(s,s') = γΦ(s') − Φ(s)`。

**动机.** 手写的稠密奖励（"多杀一个敌人 +1"、"多攒 DP +0.1"）会被策略以设计者没预料
的方式最大化。potential-based shaping 有最优策略不变的证明，是唯一在数学上安全的加速手段。

**执行.**
- 奖励函数集中在一处实现，附单元测试断言其 potential-based 形式。
- 新增任何非 potential-based 项，需要在本文件登记例外并说明为何可接受。

---

## I-5 模拟器不是真相，是假设——而且它的可信度是被**测量**出来的

**约束.** 模拟器的每一个未从数据直接读出的常数都是**标定参数**，必须登记在
`docs/SIM_SPEC.md`，带上当前取值、来源、以及"如果它错了会怎样"。
更进一步：**模拟器被允许用来干什么，由证据决定，不由默认值决定。**
`ato.fidelity.FidelityLedger` 按关卡、按机制记录 sim-vs-real 对拍证据，
并给出信任等级。**没有证据 = `UNKNOWN` = 什么都不许干**，不是"大概没问题"。

**动机.** 用户明确指出："自我模拟对局需要格外把握好对局是否准确，否则可能会出大问题。"
最危险的失败模式是**利用模拟器 bug**：策略发现某个物理上不存在的操作在模拟器里稳赢，
离线指标漂亮，实机一塌糊涂。而这种失败在纯离线的指标里**完全看不出来**。

**执行.**
- 未建模机制不静默忽略：`ato.sim.registry` 里查不到的键会产生 `NoveltyEvent`，
  strict 模式直接抛异常。**训练一律 strict**。
- 信任等级是分层的，因为"能预测通不通关"和"能预测每只怪什么时候死"是两个难度：
  `UNKNOWN < UNTRUSTED < TRIAGE < IMITATION < PLANNING < TRAINING`。
  把它们压成一个"模拟器好不好"的布尔值，正是项目会在一个只验证过简单问题的模型上
  开始训练的原因。
- 信任被**最差的一次观测**封顶，不是被平均值。偶尔错得很离谱的模拟器不能用来训练。
- 降级立即生效，升级需要连续多次一致证据。乐观地误判模拟器会静默污染训练；
  悲观地误判只浪费时间。这个不对称是故意的。
- **sim-vs-sim 的一致性永远不能晋级到 `TRAINING`。** 两次模拟跑得像，只说明它对自己
  一致，跟真实游戏无关。只有来自实机或录像的 grounded 证据才能解锁奖励生成。
- 游戏数据版本变化即作废该 scope 的既有证据：一次平衡性调整可以让上周正确的标定失效。
- 训练时对标定参数加噪；只在单一参数取值下成立的优势视为 sim exploit。

## I-6 对抗式课程必须有界

**约束.** 自动课程生成器不得自由改写关卡。它只能在已登记的扰动算子内操作
（调波次密度、敌人等级、可用干员数、初始 DP、生命上限），且每个生成关卡必须通过
**可解性检查**才进入训练集。真实关卡分布必须始终占训练数据的多数。

**动机.** 无约束的 UED 会滑向两个退化解：造出不可能通关的关卡（策略学会摆烂），
或造出平凡关卡（策略学不到东西）。regret-based 目标缓解但不消除这个问题。

**执行.**
- 扰动算子是显式注册的白名单，不是任意 JSON 改写。
- 生成关卡先由搜索规划器求解，无解者丢弃；过易者（随手就过）降权。
- 每轮训练数据中真实关卡占比有下限，写死在配置里。

## I-7 泛化是被测量的，不是被声称的

**约束.** 每次门禁评估必须分开报告四个切片：
(1) 训练中见过的关卡；(2) 未见过的关卡；(3) 未见过的干员；(4) 未见过的练度组合。
只有 (2)(3)(4) 同时不退化，才允许晋级。

**动机.** 在训练关卡上刷分是最容易的自欺。

**执行.** 评估套件在 `ato.evolve` 中定义，切片划分固定并版本化；
门禁读取的是切片指标，不是总平均。

## I-9 真实对局是第一学习信号，模拟器是被校验的前瞻模型

**约束.** 系统的学习必须以**真实游戏中的对局**为主要来源。模拟器的角色是
"被真实对局不断修正的心智模型"，用于前瞻推演与生成候选计划——不是训练数据的
主要产地。任何模拟对局产出的训练信号，都必须先通过 I-5 的信任门禁。

**动机.** 用户要求："更倾向于和真人一样，从游戏中学习并持续进化。"
这不只是风格偏好，它修掉了一个真实的架构风险：纯模拟器训练出的策略，其能力上限
是**模拟器的保真度**，而不是游戏本身。人类高手也在脑内推演，但他们的模型被每一场
实战修正，而且他们知道自己什么时候没把握。

**执行.**
- 每一场实机对局同时产出三样东西，缺一不可：
  1. 学习轨迹（观测、动作、结果）——进经验池
  2. sim-vs-real 发散报告——进 `FidelityLedger` 并驱动标定拟合
  3. 未建模机制标记——进 novelty 队列
- 对局轨迹 `BattleTrace` **只记录屏幕上读得到的量**（DP、击杀数、生命数、时钟、
  我方自己发出的动作）。这条约束是可对拍性的前提：含有敌人精确血量的轨迹，
  永远无法与真实对局比较。
- 计划在被采纳前必须通过**标定集成检验**（`ato.fidelity.ensemble`）：
  同一计划在 K 组采样标定下运行，若成败会翻转，判定为 `SIM_DEPENDENT` 并拒绝。
- 失败复盘优先使用真实对局记录；反事实推演只在该关卡信任等级 ≥ `PLANNING` 时可用。
- 系统必须能报出"我对这一关有多少把握"，并在把握不足时选择保守打法而非最优推演。

---

## I-8 真实账号上的不可逆操作需要人类确认

**约束.** 消耗理智药、抽卡、消耗合成玉、清空仓库材料、放弃活动奖励一类不可逆操作，
默认需要人工确认。自动化只覆盖可重复、低风险的日常。

**动机.** 自我进化循环会在无人看管时运行。一个 bug 造成的资源损失不可回滚。

**执行.** `ato.control` 层维护受限动作清单，命中即阻塞并请求确认。
